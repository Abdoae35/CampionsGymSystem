# OpenAPI provenance and limits

`openapi.json` is the exact Development `GET /openapi/v1.json` response from the V1 baseline plus optional Excel Bulk Import on `Excel_import_export`, captured 2026-10-17. It is OpenAPI 3.1.1 with 189 paths, **232 operations** and 131 runtime component schemas. **231 operations are controller actions**; `GET /health/database` is Development-only. The local API process was stopped after capture. Its captured server URL is temporary; configure the real frontend base URL.

`endpoint-contracts.json` remains the compiled **V1 baseline** controller inventory (227 actions and 440 reachable type shapes); the four Excel actions and their DTOs are documented in [Excel Bulk Import](EXCEL_BULK_IMPORT.md) and the refreshed OpenAPI files. `openapi.integration.json` preserves all 232 runtime operations and augments IActionResult success types, controller authorization and 11 property enum converters. The Excel actions use explicit response schemas and a service-permission explanation; the template download is marked as binary XLSX there. The integration file is **derived**, not a runtime response. Four legacy writes return 410. The financial-month export actually returns XLSX and a SHA-256 header.

These specifications cannot encode every service-level branch, Owner, Shift, employment, cash, idempotency or financial-period rule. Read the current feature workflow documents and handle 400/401/403/404/409 at runtime. OpenAPI generation does not prove Development database migration or grant activation. No business mutation was sent during capture.
