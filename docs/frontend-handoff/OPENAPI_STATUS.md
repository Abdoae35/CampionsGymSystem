# OpenAPI provenance and limits

`openapi.json` is the exact Development `GET /openapi/v1.json` response from current master `e3b8cc3` on 2026-10-16. It is OpenAPI 3.1.1 with 185 paths, **228 operations** and 128 runtime component schemas. **227 operations are controller actions**; `GET /health/database` is Development-only. The API process was stopped after capture. Its captured server URL is temporary; configure the real frontend base URL.

`endpoint-contracts.json` is a metadata-only compiled controller inventory: 227 actions and 440 reachable type shapes, zero compiler semantic errors. The runtime OpenAPI and controller operation sets match exactly after excluding Development health. `openapi.integration.json` preserves those routes and augments IActionResult success types, controller authorization and 11 property enum converters. It has 172 added response component schemas. The integration file is **derived**, not a runtime response. Nine Access Administration 200 responses already have explicit runtime schemas; four legacy writes return 410. The financial-month export actually returns XLSX and a SHA-256 header.

These specifications cannot encode every service-level branch, Owner, Shift, employment, cash, idempotency or financial-period rule. Read the current feature workflow documents and handle 400/401/403/404/409 at runtime. OpenAPI generation does not prove Development database migration or grant activation. No business mutation was sent during capture.
