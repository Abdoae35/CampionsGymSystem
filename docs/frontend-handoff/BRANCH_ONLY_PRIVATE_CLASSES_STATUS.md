## Implemented draft workflow sequence

1. With Private.View/Manage or Classes.View/Manage, read/configure branch packages (positive price, 1..100000 sessions, 1..36500 days, name <=256). No general operation key on package edit. Purchases require package's branch, Payments.Create plus module Manage, own employee Shift and drawer. FullPayment or Installment with real positive initial collection, exact parts, explicit schedule; no reservation/activation-choice API here. Classes purchase must omit CoachEmployeeId; Private selects active branch-assigned coach. Backend computes floor unit cents and final-session remainder, snapshots package, creates Sale/payment/entitlement atomically. Original Member Sales ownership stays; coaching Sale is House and Sales commission/target ineligible.
2. Private mobile: search purchased Members, inspect subscriptions/history, obtain **existing Reception Gym CheckIn ID** at same branch/BusinessDate, then `POST /api/coaching/private/subscriptions/{id}/sessions`. Actual current assigned coach must equal actor Employee even with global access. Regular non-Employee/non-standalone membership with appropriate dates/city is required; BorrowedGym/Trial do not qualify. A just-exhausted SessionBased regular membership can qualify through the explicit zero-remaining case when dates and real Gym entry match. Positive unexpired Private balance, no cancellation/overdue installments; one Private session per Reception check-in. Stable OperationId/payload exact retry, backend remaining/value evidence only. It is not coach self-entry without reception.
3. Private transfer is separate endpoint, expectedVersion, reason, different active branch coach and transferable balance. Close old assignment, preserve original coach/delivered evidence; incoming assignment on bought package is marked transferred. Owner expiry settlement requires module capability plus Branches.AccessAll, expired unused noncancelled batch, current Open branch period containing effective settlement date and unrecognized Coach period. It assigns unused value to **coach assigned at expiry**, exactly once; no fabricated attendance. This rule is code-verified and now recorded as confirmed in updated project history, superseding the earlier pending question.
4. Classes mobile: configure types and branch packages; create operation-identified occurrences with coach, read occurrences, register Members **before StartedAt**, with valid shared Classes subscription. No Reception Gym check-in prerequisite for Classes. Actual occurrence coach actor required; subscription selected explicitly or earliest expiry/created/id eligible batch, one entry per Member/occurrence, same BusinessDate, positive remaining, no cancelled Sale/overdue installments. Decrement once; use response snapshots. Complete/cancel occurs only by coach on same day after start; cancel rejects attendance. `expectedVersion` stale here is **400 BusinessRuleException**, not uniformly 409.
5. Owner targets require CoachEarnings.ManageTargets plus Branches.AccessAll, explicit per-coach/branch CommissionPeriod configuration; immutable one target rule per coach/period. Private target positive money; Classes average target positive up to four decimals. Coach must overlap branch period. Classes completed-occurrence statistics return actual total/count/average and optional target comparison; period target query dates must exactly equal period bounds. CompensationStatus is **NotConfigured**: Classes earning formula/payment is not implemented.
6. Private earnings: period progress and recognition use delivered/Owner-expiry value capped by actual net collections, deterministic delivered ordering, deferred uncollected value retained for future receipts. Source-only Private; no Classes earnings calculation. Independent explicit Private target, normal original coach 50% below / 60% reached; transferred incoming assignment fixed 50%. Missing required target leaves rate/projected earnings null. Rounding preserves cumulative source-slice rounding. Recognition requires global capability, effective BusinessDate after period end and preceding coach periods recognized (including zero), then freezes source/rate evidence and progress. It is distinct from Sales period finalization and payout.
7. Coach payout draft requires CoachEarnings.Pay + Branches.AccessAll, own Shift, positive amount <= recognized outstanding branch earnings, real Cash/InstaPay account and active ExpenseCategory. Cash availability and, specifically for this draft, noncash book balance are checked. Partial payout allocates oldest earning evidence, appends Expense/one debit/payout/balance evidence; original earning is unchanged. Existing expense returns are guarded against coaching payout expense reversal. Private refunds use existing Sales refund route and reject if new net collections would be below recognized Private eligible value; finalized-source protection still applies. No adjustment/clawback policy is invented.
